# 任务管理

## 产物与用途

产物是可追溯的任务档案，供执行者恢复工作、复现制作过程和核对验收结果。

## 输入与依赖

读取项目根目录 README.md、用户要求、相关专业 skill 和实际引用的输入资产版本。

## 生产软件

使用 Markdown 编辑器维护文档；使用实际生产软件和项目平台客户端产生工作流与执行记录。结构化记录使用 JSON，不手工伪造工具执行结果。

## 制作流程

1. 建立独立任务目录，在 task.md 记录工种、类型、目标、要求、状态、输入路径与版本、交付位置、验收标准和实际依赖。
2. 在 workflow.md 记录执行步骤、软件版本、工具、模型、提示词、参数或预演方案。
3. 执行制作，在 log.md 记录过程、失败、重试、评审结论与产物去向；同步保存实际工作流及生成清单。
4. 根据实际结果更新状态；工具执行结束、验收通过与正式入库分别记录。采用结果后按 [资产管理](../asset-management/SKILL.md) 归档。

## 格式与验收

文档使用 UTF-8 Markdown，结构化执行记录使用有效 JSON。状态使用 planned、running、review、completed、failed、cancelled。路径与版本应能定位实际输入和结果；不得将未执行的步骤记为完成。按实际输入依赖协调工作，不强制统一阶段顺序。

## 存放与归档

路径相对项目根目录：普通任务放 tasks/<task-id>/；Blender 任务放 tasks/blender/<task-id>/。task.md、workflow.md、log.md 位于任务根目录；参考放 inputs/，工程与草稿放 work/，候选导出放 output/，任务专用脚本可放任务根目录。

任务档案留在原目录；正式采用的创作产物复制到 assets/ 对应类型目录，保留任务原始结果并记录目标版本。遵循用户已有授权，不因目录规则增加审批；分镜预演的人工验收要求见对应 skill。
